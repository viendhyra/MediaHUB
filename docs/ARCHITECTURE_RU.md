# Архитектура MediaHUB 22.0

Proxmox запускает отдельную Debian VM с двумя виртуальными дисками: scsi0 для ОС и scsi1 (serial mediahub-data) для медиатеки. Cloud-init устанавливает гостевой агент, получает зафиксированный исходный коммит и выполняет bootstrap. Физические диски хоста не форматируются.

В Debian FastAPI/Uvicorn обслуживает портал на 8090. Собственный веб-плеер использует HTTP Range или FFmpeg; Android-приложение обращается к тому же API. qBittorrent (8080) загружает файлы, Prowlarr (9696) ищет источники, Radarr (7878) и Sonarr (8989) управляют импортом и отслеживанием. Они подключаются через localhost и API-ключи из root-only env.

Видео находятся в /mnt/media, SQLite — в /mnt/media/.mediahub/mediahub.db. Фоновые systemd-таймеры обновляют каталог, библиотеку и переносят завершённые загрузки. Избранное, история и карточки сохраняются в базе; отслеживаемый тайтл без файла не считается скачанной библиотекой.

Системные действия требуют частного клиентского адреса и заголовка X-MediaHub-Setup. Отдельной пользовательской авторизации пока нет. Встроенный JS и SVG работают без CDN; интернет требуется для внешних источников и GitHub.

Обновление выполняется в отдельной systemd-службе. Новый код и venv готовятся до остановки портала. Фоновые задачи приостанавливаются, создаётся SQLite backup и копия прежнего приложения. После замены проверяется /api/version; при ошибке возвращаются код, база и настройка запуска. Медиатека и настройки внешних сервисов не заменяются.
