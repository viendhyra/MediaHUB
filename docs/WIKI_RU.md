# MediaHub — вики проекта

Единая справка по устройству системы. Обновляется вместе с кодом.
Правила работы агента — в `AGENTS.md`, журнал сделанного — в `docs/AGENT_JOURNAL.md`.

## 1. Что это

MediaHub — веб-панель домашнего медиасервера с собственным плеером и Android-приложением. Она связывает в одном интерфейсе:

| Компонент | Роль | Порт по умолчанию |
|---|---|---|
| MediaHub | каталог, поиск, заметки, управление | 8090 |
| Radarr | фильмы: отслеживание и импорт | 7878 |
| Sonarr | сериалы и аниме | 8989 |
| Prowlarr | поиск релизов по индексерам | 9696 |
| qBittorrent | загрузка торрентов | 8080 |
| MediaHUB + FFmpeg | веб-просмотр и поток для приложения | 8090 |
| TMDB | метаданные и подборки (ru-RU) | — |

## 5. Ключевые механизмы

### 5.1 Библиотека и отслеживание

`cache_refresh.py` кладёт в `library_cache` всё, что знают Radarr и Sonarr, вместе с флагом `has_file`.
`season_progress()` считает сезоны и эпизоды, `library_status_label()` превращает это в статус:

- `complete` — всё на месте, подпись «✓ Все N сезонов» или «✓ В библиотеке»;
- `partial` — часть сезонов или серий, подпись «◐ N из M сезонов · X/Y эп.»;
- `tracked` — файлов нет, подпись «⏳ Отслеживается · файлов нет».

Если файлы лежат в медиатеке, но ARR их не импортировал, `/api/library-cached` всё равно отдаёт `partial` с пояснением — состояние берётся не только из Sonarr/Radarr, но и с диска.

`/api/add` после добавления в ARR сразу пишет строку с `has_file=0`, поэтому карточка честно показывает «ждём файлы», не дожидаясь следующего обновления кэша.

### 5.1.1 Удаление тайтла

`/api/library/delete` убирает тайтл целиком: файлы с диска (`delete_files=1`), тайтл из Radarr или Sonarr (`stop_tracking=1`), карточку из `library_cache`, ручные данные из `manual_meta` и метку из `user_tracking`. Задачи qBittorrent, чьи файлы лежали внутри папки, снимаются без удаления файлов клиентом — их удаляет сам MediaHub.

Проверки те же, что и в проводнике: `safe_media_path()` и `can_delete_path()`, поэтому корни разделов и `.mediahub` удалить нельзя. Если отслеживание оставить, ответ содержит предупреждение: ARR скачает удалённое заново. Если оставить файлы, предупреждение другое — карточка вернётся при следующем сканировании.

### 5.1.2 Страница-источник и объединение проектов

Если к проекту привязана страница (`manual_meta.source_url`), она — единственный источник карточки: `apply_manual_meta()` берёт название, год, постер, описание, жанры и рейтинг только с неё, а поля TMDB/Jellyfin/ARR (`FOREIGN_META_FIELDS`) обнуляет. `/api/media-details?path=` для такого проекта отдаёт `library_page_card()` и не ходит во внешние каталоги; сезоны считаются по диску. `apply_manual_library()` в `cache_refresh.py` накладывает ручные карточки последним шагом `refresh_local()`. Жанры и рейтинг лежат в `manual_meta.extra_json`.

`/api/library/merge` (`source_*`, `target_*`, `season`) переносит файлы присоединяемого проекта в папку основного через `move_merge()`: сериал — в `Season NN` (номер из `guess_merge_season()`, если не задан), фильм — в папку фильма. Серии, лежавшие в корне основного проекта без Sonarr, сначала складываются в `Season 01`. Карточка и `manual_meta` присоединённого проекта удаляются, его тайтл снимается с ARR, задачи qBittorrent снимаются.

### 5.2 Поиск релизов

Цепочка: `smart_search_plan()` → `prowlarr_search()` по каждому индексеру → `release_relevance()` → `release_playback()` → `release_smart_score()`.

`release_playback()` определяет по названию, заиграет ли раздача: образы дисков (ISO, BDMV, VIDEO_TS, AVCHD, DVD9/DVD5, BD25–BD100, «Blu-ray Disc») и RMVB MediaHUB не воспроизводит. При включённой настройке `skip_unplayable` такие раздачи убираются из списка, а `/api/provider-grab` отвечает 409, пока не придёт `force=1`. «TS» в названии считается TeleSync, «BDRemux» и «BDRip» — обычными раздачами. Те же уровни поддержки (`format_support()`) проводник показывает у файлов и папок.

`release_relevance()` разбирает название релиза на части (по «/»), убирает технический мусор (`BDRip`, `1080p`, `WEB-DL`, номера сезонов) и сравнивает с ожидаемыми названиями карточки. Год в названии релиза должен отличаться не более чем на 1 год для фильмов и 3 года для сериалов. Отсеянные релизы показываются только если ничего не осталось — с пометкой «Другое кино?».

### 5.3 Локальная база каталога

`/api/browse` хранит карточки в `browse_cache` по «корзине» (вид + жанры + настроение + сортировка + год). Первый запрос тянет 10 страниц TMDB, «Показать ещё» — по 15 страниц, пока не будет достигнут `browse_target()` (по умолчанию 1000) или TMDB не закончится.

### 5.4 Хранилище

`/api/storage/usage` считает `du` по каталогам `movies`, `tv`, `anime`, `inbox`, остальное вычисляет как разницу с занятым местом тома, добавляет список дисков из `system_setup.storage_overview()` и пользовательские подписи из `disk_labels`. Результат кэшируется на 20 минут в `mediahub_settings`.

### 5.5 Заметки

Заметка сохраняется сразу, затем `_note_resolve()` ищет карточки через `catalog_search_live()` и сохраняет до шести кандидатов. Кнопка «Отслеживать» вызывает тот же код, что и `/api/add`, и помечает заметку статусом `tracked`.

### 5.6 Слои кэша и его размер

| Слой | Что хранит | Срок жизни |
|---|---|---|
| `tmdb_detail_cache` | карточки TMDB | 90 дней для тайтлов из библиотеки, 7 дней для остальных |
| `api_cache` | ответы Radarr/Sonarr lookup, поиска TMDB и AniList | 7 дней, не более 4000 записей |
| `release_prefetch` | найденные релизы по карточкам | «свежесть» 12 часов, сами данные хранятся до очистки |
| `browse_cache` / `browse_state` | локальная база каталога, до 1000 карточек на подборку | до очистки |
| `catalog` | домашние полки | перезаписывается обновлением внешнего кэша |
| `search_release` | токены выбранных релизов | 3 дня |
| `fs_scan_<kind>` (в `mediahub_settings`) | результат обхода медиатеки | 10 минут |
| `storage_usage_cache` | разбивка занятого места | 20 минут |

Размер базы ограничен настройкой «Максимальный размер кэша» (по умолчанию 50 ГБ). Раз в шесть часов и по кнопке «Очистить сейчас» выполняется `enforce_cache_limit()`: записи удаляются от наименее ценных к более ценным (токены релизов → ответы API → неудачные поиски → старые релизы → карточки каталога → метаданные не из библиотеки → внешние новинки → история), затем выполняется `vacuum`. Библиотека, ручные привязки, избранное, заметки и наблюдения не удаляются никогда.

## 7. Обновление

С Windows: `DEPLOY_MEDIAHUB.bat` рядом с папкой проекта — собирает архив, копирует по scp, запускает `install.sh` и `CHECK_INSTALL.sh`.
Вручную — см. `docs/QUICK_START_RU.txt`.

`install.sh` перед перезапуском службы компилирует исходники; синтаксическая ошибка останавливает установку и оставляет работать старую версию.

## 8. Диагностика

| Симптом | Куда смотреть |
|---|---|
| Пустая главная | «Источники» → состояние TMDB, `/api/discovery-health` |
| Нет релизов | привязки индексеров, `/api/provider-test`, строгое совпадение в расширенных настройках |
| Карточка «в библиотеке», но файлов нет | `library_cache.has_file`, блок «Ожидают файлов» |
| Служба не поднялась | `journalctl -u mediahub -n 100` или `/api/service/logs?key=mediahub` |
| Мало места | «Сервисы» → «Хранилище и диски» |

Импорт по ссылке: `/api/torrent-page-preview` показывает данные страницы и наличие торрента. В загрузках выбираются категория, сезон и новый либо существующий проект. Поддерживаются ссылки AnimeMobi `index.php?do=download`.

Установщики Windows: INSTALL_PROXMOX.bat создаёт новую Debian VM; UPDATE_MEDIAHUB.bat обновляет уже установленный сервер по SSH. Пароли вводятся стандартным OpenSSH и не сохраняются проектом. PUBLISH_GITHUB.bat публикует доработки из Git-клона.

### Импорт по ссылке (v21.37)

В «Загрузках» вставьте ссылку и нажмите «Получить данные страницы» (разбор также начинается после выхода из поля). Карточка покажет данные проекта; список «Найденные раздачи» содержит варианты .torrent и magnet, включая соседние релизы на странице. У каждой ссылки есть название и подпись. Выберите одну ссылку, категорию, сезон и новый либо существующий проект, затем нажмите «Добавить и скачать». При единственной ссылке она выбирается автоматически.

`POST /api/torrent-page-preview` возвращает `meta`, `links`, `pageToken`, `torrentCount`. `POST /api/torrent-upload` принимает `selected_url` и `page_token`; предпросмотр хранится в памяти 30 минут (до 128 страниц) и проверяет принадлежность выбранной ссылки. При нескольких ссылках без выбора сервер возвращает 409. Перезапуск сервера требует повторного предпросмотра. Не найденные поля не заменяются данными случайного внешнего проекта.

Поддерживаются обычные HTML-страницы, JSON-LD/OpenGraph, кнопки с data-url/data-href и строковые URL в скриптах. JavaScript страницы не исполняется. Вход в закрытые сайты, CAPTCHA и ссылки, появляющиеся только после выполнения JS, автоматически не обходятся. Для таких страниц можно приложить вручную скачанный .torrent. Размер страницы ограничен 4 МБ, торрента — 20 МБ, список — 80 ссылками.

С v21.38 установщик компилирует EXE-помощник из MEDIAHUB_SSH_ASKPASS.cs встроенными средствами Windows PowerShell/.NET. EXE хранится в `%LOCALAPPDATA%/MediaHub/bin`, пароль продолжает храниться отдельно через Windows DPAPI. CMD-помощник больше не используется: OpenSSH Windows не запускает его напрямую. BAT записан в ASCII с окончаниями строк CRLF; русский интерфейс выводит PowerShell.

### Доступ к внешним страницам

Для недоступных сайтов можно настроить отдельный MEDIAHUB_PAGE_PROXY или общий MEDIAHUB_OUTBOUND_PROXY. Сервер поддерживает эти переменные, но персональные Windows-каналы и зашифрованные SSH-пароли не входят в публичный комплект. В локальной рабочей копии владельца прежние инструменты сохраняются отдельно.

### Встроенный веб-плеер (v21.41)

Откройте скачанный проект в библиотеке и нажмите «Смотреть», либо выберите видео в «Файлах проекта». Плеер поддерживает выбор серии, предыдущую/следующую серию, автоматическое продолжение, полный экран, громкость и перемотку. Пробел — пауза; стрелки — ±10 секунд; Escape — закрытие. Настройки звука и субтитров относятся к текущему файлу.

Совместимые MP4/WebM открываются напрямую с HTTP Range. Другие видео передаются через FFmpeg в H.264/AAC до 720p; выбор другой звуковой дорожки также включает этот режим. Требуются FFmpeg и FFprobe (новый install.sh устанавливает ffmpeg); уже установленный комплект /usr/lib/jellyfin-ffmpeg также подходит, служба Jellyfin для просмотра не требуется. Одновременно допускаются два потока конвертации, прямые просмотры этим ограничением не затрагиваются. Совместимый режим требует MediaSource; для первой версии рекомендуются Chrome/Edge.

Внешние .srt/.vtt должны лежать рядом с видео и начинаться с его имени, например «Серия 01.rus.srt». Встроенные в контейнер и графические субтитры в первой версии не поддерживаются. История общая для домашнего сервера, хранится в playback_history по пути и отпечатку файла. Позиция сохраняется каждые 10 секунд, при паузе и закрытии; незаконченные просмотры появляются на главной. Перемещение/переименование файла не переносит его историю. Просмотр начинается с уже скачанных файлов медиатеки; незавершённые торренты не предназначены для этого плеера.

API: GET /api/player/session (плейлист и дорожки), GET/HEAD /api/player/file (Range), GET /api/player/stream (конвертация с start/audio), GET /api/player/subtitle (WebVTT), POST /api/player/progress. Все файлы проверяются на принадлежность медиатеке, включая разрешение символьных ссылок. Кодировщик завершается при обрыве клиента.


### Экран просмотра и полный экран (v21.42)

В карточках библиотеки осталась кнопка «Смотреть». Она открывает отдельный экран проекта с сезонами и карточками скачанных видео, прогрессом, последним просмотром и продолжением. Переименование, объединение, удаление и данные по ссылке доступны через «О проекте». GET /api/player/project возвращает плейлист и историю без FFprobe каждого файла; завершённая последняя серия предлагает следующую. Миниатюры серий используют постер проекта, а не кадры видео.

В полном экране видео занимает весь экран с сохранением пропорций. Управление размещено поверх кадра и скрывается через 2,8 секунды воспроизведения; движение мыши, касание или клавиатура показывают его снова. На паузе управление остаётся видимым. Escape сначала выходит из полного экрана, затем закрывает плеер.

Совместимый поток H.264 теперь сохраняет исходную картинку без перекодирования, звук приводится к AAC. В выборе качества «Авто» использует этот режим, если он возможен; иначе выбирает быстрые 480p для HEVC/AV1 на сервере с четырьмя или менее ядрами, 720p в остальных случаях. Можно явно выбрать 480p или 720p. «Оригинал» доступен для H.264. Конвертация использует ultrafast и ограничение битрейта, оставляя одно ядро для остальных задач при наличии нескольких ядер. HEVC на старых процессорах всё равно зависит от мощности сервера, диска и сети.

### Главная без истории Jellyfin (v21.43)

На главной показывается только продолжение просмотра встроенного плеера MediaHub. Полка Jellyfin убрана; /api/home больше не запрашивает её историю. Остальные подключения Jellyfin сохраняются.

## Превью серий (21.46, Android 0.5.1)

GET /api/player/project добавляет каждому видео thumb и previewFrames (три URL). GET /api/player/thumbnail?path=...&frame=0..2 возвращает JPEG 480x270. URL содержит версию сигнатуры файла для клиентского кэша. Генерация ленивая через FFmpeg, без звука, один процесс и один поток; диск-кэш рядом с CACHE_DB в player-previews, до 2048 кадров. На Android выбранная серия показывает зацикленную плавную смену трёх кадров, без второго видеоплеера; недоступный кадр заменяется обложкой.


## Плеер и обложки (21.47, Android 0.5.2)

Веб-плеер содержит панели «Серии» и «Настройки». Серии группируются по сезону, показывают реальные кадры и прогресс. «Следующая серия» и выбор карточки переиспользуют полноэкранный контейнер. Громкость, автоматический переход, качество и выбор звуковой дорожки сохраняются при смене файла. Escape закрывает панель, затем выходит из полного экрана, затем закрывает плеер. Анимации отключаются при prefers-reduced-motion.

GET /api/artwork?url=... принимает публичный HTTP/HTTPS URL и возвращает проверенное JPEG/PNG/WebP/GIF. Использует существующий fetch_page_resource и настроенный канал импорта страниц, проверку адресов и перенаправлений, размер до 8 МБ, таймаут запроса 28 с, до трёх загрузок одновременно. Дисковый кэш рядом с CACHE_DB в artwork содержит до 2048 изображений, старые удаляются пакетами по 256; клиентский Cache-Control — 86400 с. HTML и локальные адреса отвергаются. Недоступный источник остаётся недоступным, наличие кэша не гарантирует получение удалённой картинки.

На ТВ в Android 0.5.2 закреплена компактная шапка главной и карточки проекта, есть безопасные поля по краям. Размеры карточек и число колонок зависят от размера текущего окна в dp. Прокручивается содержимое, а заголовок остаётся видимым. APK остаётся одним: /static/MediaHub.apk?v=0.5.2.

### Прозрачное управление (v21.50)

В обычном и полном экране видео заполняет окно, а заголовок и компактные кнопки лежат поверх кадра с градиентным затемнением. Белые пиктограммы: пауза/просмотр, предыдущая и следующая серия, ±10 секунд, звук, серии, настройки, полный экран. Подписи доступны через aria-label/title, клавиатурный фокус сохраняет HUD. На паузе появляется центральная кнопка. Громкость раскрывается при наведении/фокусе. Управление скрывается через 2.8 секунды воспроизведения; движение, касание и клавиатура показывают его снова. Серии/настройки — полупрозрачные панели; в узком портретном окне меню превращается в нижнюю панель. CSS учитывает prefers-reduced-motion. Внешних библиотек для плеера нет.

### Титры и интерфейс ТВ (v21.51 / Android 0.5.3)

POST /api/player/progress отмечает завершение при ended=1 либо position >= max(duration * 0.85, duration - 180). Для обычной 24-минутной серии это последние три минуты; для коротких видео порог ограничен 85% длительности. Позиция сохраняется, воспроизведение не обрывается. Чтение истории учитывает прежние записи с таким остатком. /api/player/project возвращает обновлённые completed/watched и следующую серию; /api/player/session без явного file выбирает следующую после последней завершённой. Явный выбор завершённой серии запускает её сначала. Сигнатура файла по-прежнему проверяется.

Пульт телевизора (21.52 / 22.1). Телефон отправляет команду через портал, ТВ получает её долгим опросом; прямого соединения устройств нет. GET /api/remote/poll?device=&name=&ack=&wait= — ТВ ждёт команду до 30 с; команда остаётся в очереди, пока следующий опрос не подтвердит её через ack, срок жизни 90 с. POST /api/remote/send (device, action: play/toggle/pause/resume/back/forward/seek/next/stop; для play — path проекта и необязательный file, restart, title, poster, kind) проверяет папку проекта и принадлежность файла. POST /api/remote/state — что идёт на ТВ (active=0 — ничего, away=1 — приложение на ТВ свёрнуто). GET /api/remote/devices — ТВ в сети. Состояние хранится только в памяти службы.

GET /api/player/resume возвращает {items: [...]} с незавершёнными просмотрами, отдельно от полного /api/home. Один общий источник истории для веба, ТВ, телефона и планшета.

На ТВ меню имеет ширину 64 dp с иконками и раскрывается до 180 dp при фокусе поверх содержимого, не перестраивая карточки. Шапка главной плавно уменьшается с 208 до 140 dp при выборе карточек тайтлов. Для ряда продолжения остаётся полная шапка с кнопками просмотра и подробностей. В проекте название, сведения и блок просмотра закреплены; описание, релизы, сезоны и серии находятся в прокручиваемой области. Телефон сохраняет прокрутку всего проекта и расширенное управление. APK единый: /static/MediaHub.apk?v=0.5.3.


## Выпуск 22.0: распространение и обновления

- `scripts/proxmox-install.sh`: официальный Debian 13 cloud-образ с SHA-512, новая VM и cloud-init; `scripts/bootstrap.sh`: только внутри новой VM.
- `scripts/update.sh`: фиксированный GitHub-коммит, staging-окружение, блокировка установки, резервная копия и откат. Команда `mediahub-update`. Переход с 21.x через `scripts/adopt.sh`.
- `scripts/remove-jellyfin.sh`: явная команда удаления старого сервера с копией настроек.
- `GET /api/apps`: версия, размер и SHA-256 размещённого APK. `GET /api/apps/android/download`: файл вложением.
- `GET /api/updates`: версия и новости с GitHub, `POST /api/updates/install`: выбранный коммит, `GET /api/updates/status`: состояние и журнал. Все обновления ограничены текущим механизмом локального доступа; POST требует X-MediaHub-Setup.
- Jellyfin не входит в комплект, UI и managed services. Старые обработчики оставлены для совместимости, ключ в новом backend отключён; база и медиа не удаляются.
- Единственный Android-пакет лежит в `static/`, описание в `android.json`. Сборочный проект Android и ключи подписи ведутся отдельно.
