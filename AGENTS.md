# Правила работы с проектом MediaHub

Этот файл читает любой агент (Claude Code и другие) **перед** тем, как что-то менять.
Цель — не переделывать по несколько раз одно и то же и не ломать уже работающее.

## 1. Обязательный порядок действий

1. Прочитать `AGENTS.md` (этот файл).
2. Прочитать `docs/AGENT_JOURNAL.md` — там журнал уже выполненных задач. Если задача там есть и помечена как «сделано», её не переделывать, а проверять и дополнять.
3. Прочитать `docs/WIKI_RU.md` — устройство системы, страницы, API, схема базы.
4. Только потом менять код.
5. После изменений: обновить `VERSION.txt`, `CHANGELOG.md` и добавить запись в `docs/AGENT_JOURNAL.md`.

## 2. Границы

- Backend — только `app.py`, `cache_refresh.py`, `system_setup.py`, `download_organizer.py`.
- Frontend — один файл `templates/index.html` (разметка + весь JavaScript) и `static/app.css`.
- Внешних библиотек и CDN нет и не добавлять: сервер работает в локальной сети без интернета для фронтенда. Иконки — только встроенный SVG-спрайт в начале `index.html`.
- Не добавлять сборщики (webpack, npm). Стиль кода в проекте компактный, одна логическая единица в строку — держаться его.

## 3. Что нельзя ломать

- Совместимость с systemd-юнитами: `mediahub.service`, `mediahub-cache.timer`, `mediahub-local-cache.timer`, `mediahub-organizer.timer`.
- Путь базы: `MEDIAHUB_CACHE_DB` из `/etc/mediahub.env`, по умолчанию `<MEDIA_ROOT>/.mediahub/mediahub.db`.
- Все таблицы создаются через `create table if not exists` в `cache_db()`; миграции — только добавлением колонок, без `drop`.
- `install.sh` перед перезапуском службы выполняет `compileall`. Не удалять эту проверку.
- Русский язык интерфейса. Все новые тексты — по-русски.

## 4. Правила по функциональности

- **Отслеживание ≠ библиотека.** Если ARR только мониторит тайтл и файлов нет, `has_file=0`, статус `tracked`, подпись «⏳ Отслеживается · файлов нет». В библиотеку карточка попадает только при наличии файлов.
- **Релизы.** Любой список релизов проходит `release_relevance()`: сверка названия (русское + оригинальное) и года. Несовпадающий год — отказ. Если после фильтра пусто, показываем ближайшие варианты с пометкой «Другое кино?».
- **Кэш каталога.** Локальная база — до `browse_target()` карточек на подборку (по умолчанию 1000). Значение меняется в расширенных настройках, а не в коде.
- **Долгие операции.** Всё, что может занять больше секунды (`du`, `journalctl`, поиск по индексерам), выполняется с таймаутом и кэшируется.

## 5. Стиль ответов и коммитов

- Комментарии в коде — по делу, объясняют «почему», а не «что».
- Каждая новая функция получает короткий docstring на русском.
- В `CHANGELOG.md` — только пользовательские формулировки, без внутренних деталей.

## 6. Проверка перед сдачей

- `python3 -m compileall app.py cache_refresh.py system_setup.py download_organizer.py`
- Открыть интерфейс, проверить: главная, каталог, заметки, загрузки, сервисы, установка.
- Убедиться, что версия в `VERSION.txt` совпадает с ответом `/api/version`.

## 7. Копия для GitHub и публикация

- Правки вносятся только в рабочую версию проекта. Копия репозитория GitHub обновляется синхронизацией и вручную не правится.
- Если рядом с рабочей папкой есть `AGENTS.md` уровнем выше — прочитать его: там порядок деплоя, обновления APK и синхронизации.
- После каждого изменения, установленного на сервер, обновить копию GitHub (`MediaHUB-GitHub/1_SYNC_FROM_MAIN.ps1 -Yes`), чтобы она совпадала с рабочей версией, включая APK.
- Агент не делает `git commit`/`git push` и не запускает публикацию. Репозиторий обновляет владелец после проверки.
